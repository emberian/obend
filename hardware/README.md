# hardware/

What is here, and what is not.

- `sim/` — Verilator harness for the four modules the Lean compiler emits from `.obend`
  compositions (`cleanroom_tcad_stack`, `lc_drives_userspace_stator`, `cnc_5axis_userspace_mill`)
  and from `Synth.goldenRetimedMacRtl` (`obend_retimed_mac2`). Every `.sv` in `sim/` is
  regenerated by `lean/.lake/build/bin/obend-emit-sv` and compared byte-for-byte by
  `sim/verify_sim.sh`; none is edited by hand.
- `ice40/` — the first physical target: a width-annotated emitted module placed and routed for the
  Lattice iCE40 HX1K on an iCEstick with the open toolchain (yosys, nextpnr-ice40, icestorm).
  `make` there produces a `.bin` bitstream; `make prog` loads it over `iceprog`.

Removed on 2026-11-04 (`review/EXPERT-fpga-silicon-20261103.md` §3.3, §3.7):

- `aws-f2/` (`cl_obend_shell_bridge.sv`, `synth_cl_obend.tcl`). The file declared a PCIS
  AXI4-Stream (`sh_pcis_h2c_tvalid` ...) that the AWS F1/F2 shell does not expose (PCIS is a 512-bit
  AXI4 memory-mapped slave; the CL port list is fixed by the HDK's `cl_ports.vh`), its AXI-Lite read
  channel violated the protocol, and its Tcl was an out-of-context synthesis that cannot produce an
  AFI. A real F2 custom logic is written against the HDK on an F2 instance, not guessed here.
- `sim/silicon_elab_top.sv`. It was one of three different `silicon_elab_top` designs in the tree.
  The single one is emitted by `Obend.Lower.SiliconElabFabric.emitSiliconElabFabricSV`
  (`obend hardware emit-silicon-sv`) and checked in under `apps/silicon-kernel-verilator/verilator/`.
- `sim/*_lec.smt2`. They were stale output of an older miter generator and did not match the `.sv`
  beside them. The current generator (`obend hardware emit-lec-smt2`) writes `*_belmiter.smt2`: a
  consistency check between the Lean AST and its BEL mapping, not a logic-equivalence check of the
  emitted SystemVerilog. `verify_sim.sh` regenerates them.

`rust-ffi/` is unrelated to the FPGA path (CBOR codec, FEMM/octree engines) and is owned by the
physics lane.
