## 2. The module discipline, and what Lean v4.30.0 made of it (MEASURED on probes, then on the tree)

1. **Definitional modules** (`Core.Term, Ty, Check, Machine, MachineFast, Invariant, Data, Capacity,
   Collect, Checkpoint, Extensions, MachineTyping, Interaction, Digest, Backend; Digest.*; AxiomPin,
   AssertAxioms, AssertCompiled; Slot, Slot.Protocol, Slot.Proofs.ProtocolTyping, Slot.Calculus,
   Slot.Core4`) are `module` + `@[expose] public section` around everything: a `public def` without
   `@[expose]` is opaque downstream (`unfold`, `rfl`, `simp [f]` fail: probe `modlake`), and these
   proofs unfold definitions everywhere.
2. **Proof modules** (`Core.Proofs.*`, `Slot.Proofs.{Protocol,Negotiation}`) are `module`; a theorem
   is `public` iff another module's text mentions its short name, or it carries `@[simp]`/`@[csimp]`;
   every non-theorem declaration is `public`, defs and abbrevs `@[expose]`d (a type in a public
   signature must be public; a body downstream unfolds must be exposed). Everything else is private.
   Private is what buys the iteration property: **a private theorem's proof edit rebuilds only its
   module; a public theorem's proof edit rebuilds every importer** (probe: editing `f_pos`'s proof
   rebuilt `Consumer`; editing `priv_thm`'s did not). Public theorems: 455 of 1514.
3. **Imports are `public import`** throughout: a public theorem's statement may mention anything its
   module imports, and a private import of a module whose names appear in a public signature is an
   error ("imported privately; consider adding public import").
4. **`meta`**: definitions an `elab` command uses must be `meta def` (`AxiomPin.standard`,
   `AssertAxioms.isCompilerTrust`, …; "Invalid meta definition … not marked meta").
5. **`Init` is not fully exposed to module files.** In a `module`, the kernel and `decide` cannot
   reduce through `String.toUTF8`, `Array.map`, `Array.zip`, `Array.modify`, `Array.reverse`,
   `Array.flatMap`, `List.map`, `toString (n : Nat)`; they can through `List.length`, `String.length`,
   `Array.push/size/foldl/filterMap/replicate/zipWith/any/set!`, `List.filterMap/zip/lookup/find?`
   (probe `modprobe/J.lean`). A `module` cannot import a legacy file ("cannot import non-module K
   from module"); a legacy file can import module files and then evaluates everything (probe
   `modlake`; `lake env lean` on the tree). Consequences, each recorded in the file it touched:
   - `Obend.Core.Digest.customization` is spelled as its 21 UTF-8 bytes, not `"…".toUTF8` (the value
     is identical; `deployed_eq` and the `DigestChecks` compiled pins are unchanged).
   - Seven evaluation teeth whose proofs run `collect`, `yieldedPlan`, `executeWith` or `checkpoint`
     by `decide`/`decide +kernel`/`change` moved, statements and pins intact, into **legacy leaves**
     `Obend.Core.Teeth.{Collect, CollectTyping, CollectYield, DataSoundness, Force, BackFail}` and
     `Obend.Core.Proofs.DataBudget` (the whole file is such teeth). Nothing imports a leaf. The
     theorems that consumed a moved tooth (`sampleRecord_source_semantics`,
     `sampleRecord_native_source_semantics`, `suspended_is_resource`, `exampleYield_plan_extracts`,
     `exampleYield_segment_premises`) moved with it.
6. **A `private mk ::` constructor cannot be cited by an exposed body**, even in its own module
   ("Constructor … is marked as private" for `⟨…⟩`, `Unknown constant` for `.mk`); downstream teeth
   evaluate `executeWith`, so `Data.ExtractionWith`/`ExecutionWith` have public constructors and
   "built only by `extractWith`" is now a convention in the docstring (decision D5).
7. **`#guard_msgs` on `#print axioms`** became `(whitespace := lax)`: the shorter names change where
   Lean wraps the axiom list.

## 4. The one measurement (step 4): does a proof edit cascade?

`measure.sh`, run once on the green tree (`MEASURE-20261030.log`; wall times from `date`, machine
otherwise idle, `LEAN_NUM_THREADS=2`; the log's `✔` lines omit modules that rebuilt with linter
warnings, which lake prints as `⚠`, so the "rebuilt" column below is read off the log plus the
import graph):

| step | edit | rebuilt | wall |
|---|---|---|---|
| 0 | nothing | nothing | 0 s |
| 1 | a private trivial theorem appended to `Core.Proofs.Adequacy` (5.4K lines) | `Core.Proofs.Adequacy` itself; the legacy leaves `Teeth.DataSoundness`, `Teeth.Force`, `Teeth.BackFail`; the root `Obend` (then a legacy file) | 32 s |
| 2 | an exposed `def` appended to `Core.Term`, the leaf every module imports | everything downstream of `Term`: the whole tree (41 `✔` lines plus the `⚠` modules) | 78 s |
| 3 | both reverted | the same whole tree | 78 s |

Reading. (a) The module importers of `Adequacy` (`Completeness`, `DataSoundness`,
`Preservation.Base`, `Forcing.*`, …) did **not** rebuild on a private proof edit; that is the property
the split was built for, and it holds. (b) What rebuilt besides `Adequacy` were legacy files: a legacy
importer depends on the whole transitive olean set, private parts included, so the three leaves
downstream of `Adequacy` and the then-legacy root rebuilt. The root is now a `module` (this commit);
the leaves will keep rebuilding, by their nature, at a few seconds each. (c) A definitional change at
the bottom rebuilds the whole tree in 78 s, as it would have in minidregg: the exposed section means
the module's interface *is* its bodies. (d) In minidregg the step-1 edit rebuilds the ~20 modules
downstream of Adequacy (INFERRED from its import graph, not measured there); here it rebuilds none
of them. This is one measurement on one machine, not a benchmark.

## 5. Decisions (each with a critique and a meta-critique)

**D1. Exposed sections for definitional modules, selective public for proofs.** *Alternative:* expose
only what the build demanded. *Why:* the proofs unfold everything; finding the exact exposure set is
a long build-fix loop for no iteration gain (definitional modules are leaves that rarely change).
*Critique:* an exposed section exports every helper; a definitional module's change cascades to the
whole tree (step 2), as it did in minidregg. *Meta-critique:* I optimised the case Ember named (proof
edits) and left the definitional cascade as it was; a finer split of `Check` (97 defs, 72 theorems in
one file) would cut it and I did not do it.

**D2. "Public iff another module mentions the short name."** *Alternative:* resolve names properly
through Lean. *Why:* a token scan over the tree is one Python pass; over-approximation only costs a
cascade, never a break. *Critique:* 455 public theorems is more than the true cross-module set (short
names in comments and docstrings count); every one of them cascades on a proof edit. *Meta-critique:*
the honest instrument is `lake build` with everything private, then `publicize.py` on each `Unknown
identifier`; I did the cheap over-approximation first and the exact loop only for the exposed-body
cases the build forced (17 theorems).

**D3. All non-theorem declarations in proof modules public and exposed.** *Why:* a public signature
or an exposed body that cites a private declaration is an error, and proof modules' defs
(`SourceDerivation`, `GraphRepresents`, `ReusableTerm`, …) are cited by theorems downstream.
*Critique:* a proof module's helper def is now part of its interface; editing its body cascades.
*Meta-critique:* same shortcut as D2, on defs.

**D4. Legacy leaves for evaluation teeth.** *Alternative:* `native_decide` (changes the axiom class
of a standard-pinned theorem: refused), or rewriting each proof by `simp` lemmas about `Array.map`
(weeks). *Why:* a legacy file imports module files and evaluates; the teeth import nothing else and
nothing imports them. *Critique:* seven files whose only reason is a Lean 4.30 exposure gap; when
`Init` exposes `Array.map` and friends they should fold back. The leaves rebuild on every edit
upstream (step 1), at a few seconds each. *Meta-critique:* I first put `module` headers on them by
accident (the script treats every file) and spent a build cycle on a mystery that `head -1` would
have solved.

**D5. `ExtractionWith`/`ExecutionWith` constructors public.** *Alternative:* keep `private mk ::` and
make `extractWith`/`executeWith` non-exposed, moving the two `decide +kernel` teeth that evaluate
`executeWith` to a leaf (which then could not evaluate an unexposed body either). *Why:* downstream
evaluation of `executeWith` is a tooth Ember's trees rely on. *Critique:* "evidence constructed only
by the function that checked it" was by construction in minidregg and is by convention here; a
module that forges an `ExecutionWith` is now type-correct. *Meta-critique:* this is the decision I
most want Ember to look at (§7).

**D6. `Digest` as a typeclass with no laws; `deployed := Digest.hash customization`.** *Why:* the
theorems about hashing (`binds_or_collides`) are over an explicit `Hash`; the class only names which
hash runs; a host attaches a kernel by `@[csimp]` as before. *Critique:* one instance; the class
proves nothing until a second instance exists. *Meta-critique:* the brief asked for it; the honest
measure of a class is its second instance, which is minidregg's Rust seam, not built here.

**D7. `Backend σ V` mirrors the machine's driver API with `Outcome σ V` generic in state and value.**
*Alternative:* reuse `Term.Representation` (the Prop-carrying structure). *Why:* a Leaf (Bend-compiled)
state will have its own value type; identity-on-outcomes for the demand machine
(`toMachine_ofMachine`) loses nothing. *Critique:* `Outcome σ V` duplicates `Machine.Outcome`'s five
constructors; the class carries no law, so a wrong instance type-checks. *Meta-critique:* "no laws"
was the brief; the law that matters (`runBounded` agrees with the reference) is a theorem about the
one instance, where it already was.

**D8. `Slot.Calculus` as a class over `Tm`, with `Ty`/`Ctx` as fields.** *Alternative:* nano's
`CalculusData` structure. *Why:* the brief; and `Calculus.slotOf` gives the class its consumer in
this package: a hole `[Ψ ⊢ A]` is a `Slot` whose judge is `check Ψ · A`, so `slot_repair`,
`resolve_ok`, `resolve_error` speak of fillings that are terms. *Critique:* nano deleted
`CalculusData` with the toy closure (LANG-74), so this revives a vocabulary nano's deployed path does
not use; its laws (`CalculusLaws`) are not ported. *Meta-critique:* I built what the brief named
rather than asking whether the surviving slot needed it; `slotOf` is the argument that it does.

**D9. The Core4 instance: holes are free de Bruijn hypotheses, fillings closed annotated terms,
annotations merged by walking the checker's positions.** *Why:* Core4 has no hole former; this is the
closed-hole fragment LANG-68 named for nano's `ref`. *Critique:* `check` at a hole uses the
surroundings' context, so a filling may use those hypotheses but is never itself open (depth one);
`strengthen`/`weaken` rename with no theorem relating them (`rename` composition is not in Core);
the substitution lemma (`check` preserved by `msubst` of checked fillings) is **owed**, named in the
module docstring. Four equations are proved (`annotationsAt_root`, `msubst_var_filled`,
`msubst_var_open`, `uses_var`), pinned standard. *Meta-critique:* the instance is honest about being
the small fragment; the owed lemma is the first real theorem of the Spec library, not of this step.

**D10. `Obend.Core.Teeth.*` stay in the `Obend` library and are built by `lake build`.** *Alternative:*
a separate `lean_lib`. *Why:* one target, one green. *Critique:* they rebuild on every upstream edit.

## 7. The one decision for Ember

**D5.** The module system will not let an exposed body cite a private constructor, and the trees'
evaluation teeth need `executeWith` exposed. So `ExecutionWith`, the structure whose field `runExact`
"records that a value came from the call that produced it" (minidregg's words), can now be built by
anyone. Either accept the convention, or keep the constructor private and give up kernel evaluation
of `executeWith` downstream (the two teeth would then need another form of evidence). I chose the
convention and said so in the docstring; it is the only place the extraction changed what a type
enforces.
