# Lean 4.35 toolchain bump (2026-10-31)

`lean/lean-toolchain` is `leanprover/lean4:v4.35.0` (was v4.30.0). `LEAN_NUM_THREADS=2 lake build`
passes **177 jobs**; `python3 lean/tests/run-obend-source.py` prints the same output byte for byte
before and after (probes 30/30, tutorial 71/71, preview cohort 161 items, 0 failures, the one held
stale pin unchanged). The lake manifest did not change (no packages). No theorem statement, pin or
`#assert_axioms` line was edited.

## What changed in Lean between 4.30 and 4.35 that this tree hit

Three toolchain changes account for every failure, beyond the five the probe build named:

1. **The `do` elaborator.** `backward.do.legacy` defaulted to `true` at 4.30 and `false` from 4.33.
   The new elaborator compiles `if c then throw e` (no `else`) into join points, emits fewer binds
   for trailing statements, and does not refine a `do`-level `match` on a dependent result type
   without `(dependent := true)`. The tree now uses the new elaborator; no legacy switch is set.
2. **`backward.isDefEq.respectTransparency` (default `true`).** Implicit arguments are checked at
   `.implicit` transparency, not `.default`. `rw`/`simp`/`simpa` results that agree only by unfolding
   a semireducible definition in an implicit index (a context, a graph, a `ClosedSupport`) are no
   longer accepted. Lean's intended remedy is `[implicit_reducible]` on the definitions involved.
3. **Simp set and simp behaviour.** New `@[simp]` `Bool.dite_*_eq_*` lemmas; `simp` no longer
   closes some membership goals over non-reducible index types; simp's conditional-rewrite
   discharger proves a side goal it then fails to assign ("failed to assign proof", seen on
   `finiteRow_nonrow`); `if_pos`/`if_neg`/`if_true`/`if_false`/`dif_pos` are deprecated (warnings only,
   left in place). `Lean.ofReduceBool`, `Lean.ofReduceNat`, `Lean.reduceBool` and
   `Lean.trustCompiler` no longer exist.

**Debt, named.** `equirec_reduce` keeps the 4.30 implicit-argument check for its own `simp` call
through a `backward.*` option, which Lean may remove. A partial restructuring (rewriting
`(graph a).label`/`.successors` and `FiniteSafety.mirror` by field equations instead of unfolding
the graphs) fixed two of the three `DecisionReduction` probes without the option; the third still
fails on a membership proof over `support`, and `CheckTeeth` needs the same. The lasting fix is a
reduction tactic that never unfolds a definition occurring in an index (field equations, or
`[implicit_reducible]` on the node-list definitions).
