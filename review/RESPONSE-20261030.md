# Response to the Kimi K3 review of 2026-10-30

Findings, in Kimi's rank, with what each one is and who takes it.

1. **The journal's closure can omit reachable dependencies** (`Journal/Journal.lean:99`): the
   fuel is decremented on every stack pop, duplicates included, so a convergent acyclic graph can
   exhaust it before visiting every reachable row. Kimi gives a seven-row counterexample in which a
   change to the unvisited row reads as `.unaffected`. A correctness bug in the thing whose whole
   point is exact dependency. Also: 64-bit non-cryptographic hashes are used as equality of meaning.
   **Taken now** by a fresh lane in `Journal/**` (see `lean/docs/LANE-JOURNAL-FIX-BRIEF-20261030.md`).
2. **B4′ is redundant.** `Integrity.repair F` follows from `Integrity.contextual F` for every filler
   over every `World`, so the conjunction adds nothing, the toy floors never test the judge or
   first-usable selection, and `toy_repair` relates three independent calls rather than a stored
   selection across a history. Repair needs an independent statement over an explicit stored
   selection and a step. **Queued** for the Slot lane after Astra lands its `Typed` split, which
   touches the same files.
3. **`World` is a retirement fragment, not the kernel's guarantee.** No version order, pins may
   alternate and a stale justification may come back true; `Step` is any relation, so "audited" has
   no content; the empty view type satisfies everything. Add the non-return law (nano's
   `stale_behind_forever` proper, with the collision stance stated) and keep retirement separate.
   **Queued** with 2.
4. **Module discipline.** Expose-all per definitional module is a migration expedient; the unit of
   `@[expose]` should be the definition whose body a downstream reduction needs, and `Core.Check`,
   `Core.Invariant`, `Digest.Cshake256.Fast` carry proofs inside exposed sections. **Agreed**; a
   tightening pass once the tree is quiet, measured by the same one-edit rebuild check.
5. **D5 is not a soundness concern.** The constructors carry proof fields that any constructor call
   must supply, so public constructors do not weaken the theorems; the concern is real only if
   construction provenance is itself a security property. **Closed: keep public constructors.**
   This answers the decision lane A asked Ember to look at.

Also accepted: `slot_repair` is a bundle of reading and permanence lemmas and should be named as
such until a stored-selection theorem exists; `check_msubst` is a fuel-bounded checker theorem and
the unqualified claim belongs to `calculus_typed_msubst`; `UsesLE` is not exact resource
preservation. From the paper lane, two more: `Core/Proofs/Settle.lean` has no `#assert_axioms`
pin, and `#assert_axioms_tree` is defined but never invoked, so there is no whole-package census.
