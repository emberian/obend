## 0. What moved, in one paragraph

INFERRED from §1–§12. Four of our twelve shelves have a 2022+ result that *settles* a question we had
left open with a mechanized proof: lazy cost without a heap (Xia et al. 2024, §4), the two sound pair
types under grades (Abel–Danielsson–Eriksson 2023, §2), equi-recursive subtyping as iso-recursive
subtyping plus erasable casts (Zhou–Wan–Oliveira 2024 and QuickSub 2025, §3), and intensional
analysis of code under a consistency proof (Hu–Pientka's layered theories, §1). Three shelves have
*infrastructure* that did not exist when our designs were written and that we should consume rather
than rebuild: the Lean toolchain's own kernel-proved LRAT checker and PBLean's reflected VeriPB (§7),
the `.lean`-file-plus-axiom-audit certificate every 2024–2026 LLM-prover system converged on
(§12), and Lean4Lean as a second kernel (§11). Two shelves say our designs are the mature ones
(quotation as a kernel function on held terms, §1 and §5; patches with pushouts, §10). Two shelves
offer statement *shapes* we lack: liveness for a reconciler (Anvil's ESR, §6) and a witness quorum as
the "independently selected head" (Parakeet, §6). One shelf, mutation testing of proofs, has no
2022+ literature at all (§11). The five places where a recent result changes a recorded decision are
ranked in §13; one of them (C4) was already re-decided on this evidence while the study was being
written.

## 1. Staging and quotation under a type theory
Classic we cite: Davies–Pfenning 2001, Nanevski–Pfenning–Pientka 2008 (CMTT), Kovács 2022 (2LTT staging), Tan–Wei 2026; the orientation in `review/QUOTE-ORIENTATION-20261101.md` §0–§1.
Question: typed quotation with pattern matching and hygiene, two-level type theories in practice, verified staged compilers, quotation under effects and linearity.

### Papers
- `hu-pientka2023-layered-modal-type-theories.pdf` — Hu, Pientka, 2023/24, Layered Modal Type Theories (arXiv 2305.06548; POPL 2024 line). READ. NEW.
  Delta: where Davies–Pfenning's S4 and Mœbius give composition of code, layering gives *pattern matching on code* with normalization: layer 0 is code with no dynamics (its equivalence is syntactic equality, §2 Lemma after Thm 2.6, l. 479–485), layer 1 computes over it, and `box t` lives only at layer 1 (Thm 2.3: layer-0 terms have core types, layer-1 terms have types that may mention □).
  Consequence: this is the wall of QUOTE-ORIENTATION §0 stated as a typing invariant; obend's `quote : Term → Data` in `lean/Obend/Core/Code.lean` (`shapeData (encode t)`) already makes code a layer-0 object whose equality is syntactic, and the layer theorem is the shape in which the decision "`quote` is a kernel function on held terms, no new `Term` constructor" should be recorded in `review/DECISIONS-20261031.md`.
  Statement: Thm 2.6 (substitution): local substitution exists only at layer 1 ("local substitutions do not propagate under box"); global substitution at both layers, with layer 0 subsumed by layer 1. Thm 3.8/3.9: NbE for layer 1 is sound and complete, so conversion with code analysis is decidable.
- `hu-pientka2024-delam-dependent-layered-modal-type-theory.pdf` — Hu, Pientka, 2024, DeLaM: A Dependent Layered Modal Type Theory for Meta-programming (arXiv 2404.17065; POPL 2025). READ (intro, §2, Thm 8.6). NEW.
  Delta: scales layering to MLTT with context variables (needed for recursion over code, §2) and proves decidability of conversion and consistency, so one type theory can compose, execute and intensionally analyze its own code of types and terms without losing consistency.
  Consequence: the Löb-rule decision ("the intensional fixed point is inside the knot with the description a term", taken by Claude 2026-11-01) is consistent only under DeLaM's layer invariant: the analyzer sits at a strictly higher layer than the description it analyzes; obend respects it because `splice` is a turn of the runner (`lean/Obend/Run/Adapter.lean`) and `resume` evaluates in the empty environment (`Core/Machine.lean`), and the DECISIONS row should say so explicitly.
  Statement: Thm 8.6 (Decidability of Convertibility): for `L | Ψ; Γ ⊢ᵢ T @ l` and `T'`, whether `T ⟺ T'` is decidable, and likewise for terms; proof by two instantiations of the fundamental theorem (§8). §2: "we cannot perform recursion on the structure of code" without context variables capturing local contexts as global variables.
- `jang-pientka2024-polymorphic-metaprogramming-memory-management-adjoint.pdf` — Jang, Pientka, 2024, Polymorphic Metaprogramming with Memory Management: An Adjoint Analysis of Metaprogramming (arXiv 2411.00752; Elevator). READ (intro, Thm 3.4, 3.11). NEW.
  Delta: replaces the single □ of Davies–Pfenning with adjoint modes carrying structural properties and a preorder of accessibility, so code regions can be linear (garbage-free) or persistent and the generated code carries resource guarantees; this is the first quotation calculus where linearity is a property of the code region, not an afterthought.
  Consequence: contract C2 ("ownership across aggregates and staging") has a ready statement shape: Thm 3.4 says a variable of a mode without contraction occurs at most once and without weakening at least once, and Thm 3.11 (mode safety) says evaluation never reads an inaccessible region; obend's refusal of closures in `Data` (`lean/Obend/Core/Data.lean`, `Failure.executableValue`) is the degenerate two-mode case, and a `linear` quoted value would need a third mode rather than a `Ty` flag.
  Statement: Thm 3.4 (Substructurality of Variable References): if `Γ ⊢ e : Aₖ`, `x:Bₘ ∈ Γ` and `C ∉ S(m)` then `x` occurs in `e` at most once; if `W ∉ S(m)`, at least once. Thm 3.11 (Mode Safety): for `k ≥ n`, if `Γ ⊢ e : Aₖ ≃ₙ e' : Aₖ' ⊣ Γ'` and both evaluate, the values are related at the same mode.
- `obend-vision-20261031/tan-wei2026-semantics-preserving-staging.pdf` — Tan, Wei, 2026, When Do Staging Annotations Preserve Semantics? (arXiv 2606.30854). READ (abstract, §5 Thm 5.9/5.10). ALREADY IN PAPERBIN.
  Delta: answers Inoue–Taha's question with a mechanized binary logical relation: for CBV with let-insertion tracked as a control effect, erasing annotations always preserves semantics, and with references the same holds for the extended calculus (Thm 6.4).
  Consequence: the erasure/preservation obligation for `quote` (`METATHEORY.md` §2 row "quote: observer ladder, `rewrite_sound_below`, erasure and preservation", `lean/Obend/Equiv/Quote.lean`) should be stated as contextual equivalence of the stage-erasure, and under call-by-need the let-insertion effect that Tan–Wei must track is absorbed by sharing, which is the one place obend's laziness makes the theorem easier, not harder (INFERRED).
  Statement: Thm 5.10 (Semantics Preservation): if `∅ ⊢ t₁ : rep τ | ε` and `t₁ →* code t₂` then `∅ ⊨ |t₁| ≃ctx t₂ : τ`; Thm 5.9 strengthens it to every `Γ ⊢ t₁ : τ | ε` with `|t₁| ≃ctx |t₂|`.
- `lee2026-handling-scope-checks-dynamic-scope-extrusion.pdf` — Lee, Xie, Kiselyov, Yallop, 2026, Handling Scope Checks: A Comparative Framework for Dynamic Scope Extrusion Checks (POPL 2026, arXiv 2601.18793). READ (intro, Thm 3.4, Defs 4.1–4.3). NEW.
  Delta: the first formal study of the *dynamic* scope-extrusion checks that MetaOCaml actually ships, with correctness and permissiveness defined relative to a configuration predicate, a new "Cause-for-Concern" check proved correct, and refined environment classifiers compared against it; the static/dynamic wall becomes a lattice of checks.
  Consequence: obend's `Scoped 0` requirement on slot fillings (`lean/Obend/Slot/Core4.lean`, `calculus_typed_msubst`) is the least permissive correct check in Lee's sense; if `splice` as a turn later admits open code (CMTT), Def 4.1/4.2 are the two theorems to state about whatever check the runner runs.
  Statement: Def 4.1 (Correctness): a check `⟦−⟧Check` is correct w.r.t. Φ if every closed well-typed `e` whose execution reaches a configuration satisfying Φ makes the checked program reach `err`; Def 4.2 (Permissiveness): the set of well-typed `e` the check never rejects. Thm 3.4 (Quote–Splice Duality): under a top-level splice `$⟨⟨e⟩⟩ =q e` and `⟨⟨$e⟩⟩ =s e`.
- `xie-chen-yallop2023-macocaml-staging-composable-compilable-macros.pdf` — Xie, White, Nicole, Yallop, 2023, MacoCaml: Staging Composable and Compilable Macros (ICFP 2023, 10.1145/3607851). READ (intro, Thm 4.5). NEW.
  Delta: unifies Flatt-style phased macros with MetaML-style quotation: macros are compile-time bindings, splices at top level run at compile time, and the calculus (with compile-time heaps and modules) proves phase distinction, which neither tradition had with the other's features.
  Consequence: "`splice` is a turn" and "program-level quote on values refused" (DECISIONS row of 2026-11-01) are MacoCaml's phase distinction in obend's vocabulary; Thm 4.5 is the theorem the Leaf emitter should carry when an emitted book contains compile-time (runner-time) parts (`lean/Obend/Run/Adapter.lean`).
  Statement: Thm 4.5 (Phase Distinction): given `Γ ok`, `σ ok`, `σ Γ ⊢r Ω`, if `σ Γ ⊢ M : Δ` and `σ Ω M ⟶ M' σ'` then `σ ⟦Ω⟧ ⟦M⟧ ⟶ ⟦M'⟧ σ'`, i.e. erasing compile-time parts commutes with run-time reduction.
- `kovacs-2022-staged-compilation-two-level-type-theory.pdf`, `kovacs2024-closure-free-functional-programming-2ltt.pdf` — Kovács, 2022 (ICFP) and 2024 (ICFP). READ (2022 §1, §5 stability/soundness; 2024 abstract). ALREADY IN PAPERBIN.
  Delta: 2LTT staging with stability (`Stage ⌜A⌝ = A`) and soundness (output convertible to input) is a strong conservativity theorem of the two-level theory over the object theory; 2024 adds a closure-freedom guarantee for the generated code, a resource property of output rather than of the generator.
  Consequence: the "observer ladder" for `quote` (`lean/Obend/Equiv/Quote.lean`) wants exactly Kovács's pair, stability (quoting then splicing is identity) and soundness (the staged program is convertible to the unstaged one); Kovács 2024 is the precedent for stating a *resource* property of emitted code, which is what Leaf and C4 will need.
  Statement: 2022 §5: (1) soundness, staging output is convertible to its input; (2) stability, `Stage ⌜A⌝ = A` and `Stage ⌜t⌝ = t`; together "embedding is a bijection on types and terms (up to conversion)".

## 2. Linear, graded and quantitative types
Classic we cite: McBride 2016, Atkey 2018 (QTT), Wood–Atkey 2022 (usage vectors as outputs, the shape of `PartialTyping`); Granule 2019 and Linear Haskell 2018 as practice (`review/PRIOR-ART-20261030.md` §2).
Question: graded modal types in practice; linearity with effects and aggregates (the `⊗`/`&` elimination question, contract C2); ownership in Rust-adjacent formalizations (Aeneas, RustBelt successors, Verus); resource-aware session types.

### Papers
- `abel-danielsson-eriksson2023-graded-modal-dependent-type-theory-erasure-formalized.pdf` — Abel, Danielsson, Eriksson, ICFP 2023 "A graded modal dependent type theory with a universe and erasure, formalized" (doi 10.1145/3607862; the journal version arXiv 2603.29716 is what was fetched). READ (intro, §4.3 the two Σ-types, §5 usage rules and Theorems 5.3–5.4). NEW.
  Delta: relative to Atkey's QTT it is the first fully formalized (Agda) graded dependent type theory with a universe, large elimination and *two* pair types whose usage rules differ: a tensor pair `(t,u)⊗` is used at `γ + δ` and eliminated only by `prodrec` (a destructor that binds both components under a grade), a with-pair `(t,u)&` is used at `γ ∧ δ` (meet) and eliminated by `fst`/`snd` at usage `γ`; Theorem 5.4 is preservation of grades under reduction.
  Consequence: C2's two candidate counterparts to the projection refusal (a pattern-matching destructor, or an all-siblings-shareable `get`) are exactly `prodrec` for `Σ⊗` and projection for `Σ&`; obend's `record` rule sums field uses (`Obend/Core/Check.lean` `record` via `FieldsTyping`/`addUses`, a `⊗`-introduction) while `get` is a `&`-elimination guarded by `linearFree`, so the consistent fix is either to type records as `&` (fields share one usage, `∧`, and every field may be read) or to add a `prodrec`-shaped `open r as {f₁,…,fₙ} in e` whose uses are the sum; Abel et al. §8 shows the mixed "strong graded Σ" only admits `fst` in the erased world, which is the theorem that says the current hybrid cannot be made sound by a side condition alone.
  Statement: usage rules §5: `γ + δ ▶ (t,u)⊗`, `γ ∧ δ ▶ (t,u)&`, `γ ▶ fst t` iff `γ ▶ t`; Thm 5.3 (Substitution) `γ ▶ t` and `Ψ ▶ σ` give `γΨ ▶ t[σ]`; Thm 5.4 (Subject reduction) `γ ▶ t` and `Γ ⊢ t → u : A` give `γ ▶ u`; §8 Remark: "the first projection for the strong graded Σ-type `Σ&,0` is only available in the erased setting, but the η-rule for this type is always active".
- `marshall-vollmer-orchard2022-linearity-and-uniqueness-entente-cordiale.pdf` — Marshall, Vollmer, Orchard, ESOP 2022 "Linearity and Uniqueness: An Entente Cordiale" (doi 10.1007/978-3-030-99336-8_13; the Kent OA copy). READ (abstract, §1, Theorems 4–7). NEW.
  Delta: relative to Wood–Atkey's static usage metatheory it states linearity as a *dynamic* conservation law over a heap-and-resource semantics, `(H′ + Δ) ⊑ (H, Γ₁)` across every reduction, and separates it from uniqueness (Theorem 5: a unique reference stays unique), implemented as a third modality in Granule.
  Consequence: Theorem 4 is the run-length statement C2 says is missing ("a linear conservation theorem over `Step` is the missing soundness statement"): `Obend/Core/Proofs/Conservation.lean` `step_conserves_linear` is the one-step, syntactic-count version (`occurrences` of a `linear` hypothesis preserved by a source `Step`); the entente shape, resources consumed by the step plus resources remaining bounded by resources before, is what a statement over the machine (`Obend/Core/Machine.lean`, update frames, the `Collect` lockstep) would have to look like, and its uniqueness half is the property obend's `Data`-is-copyable / everything-else-affine split (`Obend/Core/Ty.lean` `Quantity`, `Reuse`) has no theorem for.
  Statement: Thm 4 (Conservation): for well-typed `Γ ⊢ t : A`, heap `H ⋈ (Γ₀ + Γ)`, reduction `H ⊢ t ⇝ H′ ⊢ t′ | Γ₁ | Δ`: `∃Γ′. Γ′ ⊢ t′ : A ∧ H′ ⋈ (Γ₀ + Γ′) ∧ (H′ + Δ) ⊑ (H, Γ₁)`; Thm 5 (Uniqueness): array references unique in the incoming heap stay unique at the value, new ones are unique.
- `ho-protzenko2022-aeneas-rust-verification-functional-translation.pdf` — Ho, Protzenko, ICFP 2022 "Aeneas: Rust verification by functional translation" (arXiv 2206.07185). READ (intro, §2 backward functions, §4 projectors). NEW.
  Delta: relative to RustBelt's semantic model, Aeneas gives Rust borrows a *value-based* semantics (LLBC: loans and borrows as values, no addresses) and translates borrow termination into pure "backward functions" that return the owned aggregate pieces to their owners, with input/loan/output *projectors* dispatching each component of an aggregate to its region.
  Consequence: C2 asks for "a stated contract for dropping, transferring, splitting and returning aggregates and what a terminal machine state owes"; Aeneas's backward function is that contract made a function: for every borrow handed out of an aggregate, a pure function that gives back what the terminal state owes, and projectors are the per-component accounting that the obend `record` rule (`Obend/Core/Check.lean`) does only at construction. The "no interior mutability, no unsafe" fragment Aeneas covers is larger than obend's affine fragment, so the value-based semantics is a direct model for `Obend/Core/ResourceSemantics.lean` rather than a separation-logic one.
  Statement: §2 "Returning a mutable borrow, and a backward function": for `choose<'a>(b, x: &'a mut T, y: &'a mut T) -> &'a mut T` the translation emits a forward function and a backward function `choose_back : bool → T → T → T → (T × T)` applied when `'a` ends; §4 input borrow projector, loan projector, output borrow projector "dispatch each component of the argument to its respective region abstraction".
- `ho-fromherz-protzenko2024-sound-borrow-checking-rust-symbolic-semantics.pdf` — Ho, Fromherz, Protzenko, ICFP 2024 "Sound borrow-checking for Rust via symbolic semantics" (arXiv 2404.02680). SKIMMED (abstract, Theorems 2.2, 3.1–3.4). NEW.
  Delta: proves LLBC sound against a CompCert-style heap-and-addresses language and proves that LLBC's symbolic semantics is a borrow-checker (symbolically checked programs do not get stuck on the low-level model), with a `join` for loops, via "hybrid states" simulations.
  Consequence: this is the shape of the statement obend's `Elab/Proofs/Refines.lean` and `Core/Proofs/Adequacy` would need to connect the syntactic ownership check to the machine: a symbolic semantics that *is* the checker, proved to abstract the concrete one; it also tells C2 that "syntactic ownership never used to prove the runner's durable spend tokens" is the right caution, because the Aeneas soundness proof is two simulations deep before the type-level discipline says anything about the heap.
  Statement: Thm 3.4: for every PL (pointer-language) state `Ω_l` and LLBC state `Ω_h` in the forward relation, an LLBC step is matched by PL steps keeping the relation (forward simulation through the hybrid language HLPL+); Thm 2.2 (forward simulation on the superset language) is the proof device.
- `villani-hostert-dreyer-jung2025-tree-borrows.pdf` — Villani, Hostert, Dreyer, Jung, PLDI 2025 "Tree Borrows" (doi 10.1145/3735592). SKIMMED (abstract, §1, §5 overview). NEW.
